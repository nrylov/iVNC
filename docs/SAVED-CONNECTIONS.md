# Saved connection and foreground reconnect

## Native client (0.15)

Enable **Remember connection securely** and connect. After the first displayed
frame, the native app saves one connection including password, enhanced /
compatibility mode and pipeline preference. It uses its own app-scoped Keystore
key and encrypted preferences, separate from the hybrid client. Saved passwords
appear as a hint and are never inserted into a password text field.

Switching away closes the active session; returning reconnects automatically.
A saved connection with active resume intent also reconnects after process
recreation. Manual **Disconnect** or login/permission rejection disables that
intent. **Forget saved connection** stops the session, clears the saved entry/key
and prevents automatic reuse. Unchecking Remember before connecting removes the
saved entry. A continuously foreground network failure has no automatic retry loop.

Galaxy synthetic tests verify these behaviors, zero-size startup/zoom retention,
stale callback rejection, rejected-login suppression and recovery from unreadable
saved data. Tests use separate keys/preferences and an in-memory clipboard; actual
Mac 0.15 verification is pending.

```sh
./scripts/device.sh shell am instrument -w -r \
  dev.ivnc.nativeclient/.SavedSessionInstrumentation
./scripts/device.sh shell am instrument -w -r \
  dev.ivnc.nativeclient/.ProfileStoreInstrumentation
```

## Hybrid client history

Android 0.5 adds one saved connection, including its Mac login. Enable
**Remember connection, including password**, then connect successfully. The app
saves only after authentication succeeds. Later launches fill the connection
form; press Connect to start the session. The current viewer still uses noVNC.

**Reconnect when returning to the app** retains the session intent while the
process lives. Switching away closes TCP/UDP and stops video admission before
the WebView/Surface pauses. Returning reconnects using the in-memory details.
Duplicate lifecycle/visibility events are idempotent. An explicit Disconnect or
an authentication failure prevents automatic lifecycle reconnect. The option can
be disabled independently of remembering the login.

**Forget saved connection** deletes the encrypted entry and its Keystore key,
clears the password field and disables automatic reconnect. An already open
session can continue; Disconnect releases its retained connection intent.
Unchecking Remember also removes the saved entry.

## Storage

`ProfileStore` encrypts the complete profile using AES-256-GCM and a fresh IV for
each save. Its key is generated by Android Keystore, is app-scoped and requires
an unlocked device. SharedPreferences contains the IV and authenticated
ciphertext, rather than plaintext login details. The application disables
Android backup. Profiles do not use WebView localStorage and are excluded from
diagnostic reports, source files and logs.

The encrypted profile contains the address, port, username, password, selected
video/mouse modes and reconnect preference. If the key is unavailable or the
ciphertext fails authentication, loading reports an error rather than using
plaintext fallback. Forget the unusable entry and enter the details again.
There is no biometric prompt on each connection. Login details necessarily exist
in app memory while authenticating and while automatic reconnect is enabled.

## Validation

- Node: 465 protocol/adapter/profile/reconnect tests pass. Includes duplicate
  lifecycle events, manual stop, disabled reconnect, failed authentication,
  profile restoration, opt-out and Forget behavior.
- Galaxy: `ProfileStoreInstrumentation` passes Android Keystore round-trip
  across store instances, absence of plaintext in the saved entry, fresh
  encryption per save, ciphertext tamper rejection, invalid-save rejection and
  Forget. It uses a dedicated test preference file/key and never reads the
  owner's saved credentials.
- Galaxy: sparse stripe, coalesced worker and Surface-restore tests still match
  the independent Mac pixel reference after lifecycle integration.
- Real WebView: saved-connection controls and lifecycle handlers are bound.
  Owner's connection showed successful encrypted save; live event history then
  showed a clean background pause and automatic High Performance reconnection
  on return, followed by another clean pause, without a fallback/overflow.

Run the store instrumentation with:

```sh
./scripts/device.sh shell am instrument -w -r \
  dev.applescreen.prototype/.ProfileStoreInstrumentation
```

Instrumentation interrupts the current app session. SDK/tools/caches remain
project-local; only the owner's previously authorized ADB keys use `~/.android`.
